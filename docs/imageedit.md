# 图片编辑（编辑图片、创造拼图、合并文档）

从 CLAUDE.md 拆出来的细节：改这部分代码前先读。

## 实现

代码按需加载：`src/toolbox.ts` 的 `lazyTool` 第一次打开这个工具时才 `import("./imageedit")`（连同拼图、合并文档、去背景、去水印约 95KB），所以别的模块别静态 import 它。

- `imageedit.go` + `src/imageedit.ts` + `src/marks.ts`：工具「图片编辑」（2026-11-18 加，侧栏在屏幕录制后面）。打开：「打开」（`ImageEdit.Open`）、拖进窗口（`ImageEdit.OpenPath`）、Ctrl+V 粘贴（页面直接读 File），以及别的工具的「编辑」——截图工具栏的「编辑」（快捷键 E，`Shot.Finish(…, "edit")`；空状态的「截图编辑」是 `Shot.start("edit")`，松开鼠标直接打开）、贴图右键「在图片编辑里打开」、剪贴板历史图片的「编辑」（`Clips.Edit`）：Go 的 `ImageEdit.edit` 把 PNG 放进 `imgedit` scheme（`http://imgedit.localhost/<序号>`，带 `Access-Control-Allow-Origin: *` 才能读回 canvas，只留最近 3 个），`showTool("image")` 并广播 `imageEditOpened`，页面 `ImageEdit.Take` 取一次。编辑全在页面的 canvas 上：图片是「原图 + 操作列表」（crop/rotate/flip/resize/adjust/mark/frame），撤销就是去掉最后一个、从原图重放（不留每一步的位图），重做照做；`doc` 是模块变量，切到别的工具再回来还在，有未保存修改时打开新图或关闭要确认。面板（左栏，记在 localStorage `image-mode`）：裁剪旋转（比例、宽高输入、回车/双击裁剪，左右转、翻转）、调色（8 个带缩略图的滤镜 + 亮度/对比度/饱和度/色温/色相/锐化/模糊；预览是给画布加 CSS `filter`，应用时用同一串给 `ctx.filter`；色温和锐化是页面里按值生成的 SVG 滤镜 `#ie-fx-<色温>-<锐化>`（feColorMatrix + feConvolveMatrix），`ctx.filter = "url(#…)"` 在 WebView2 上实测生效）、标注（和截图共用 `src/marks.ts` 的 `paintMarks`，坐标是图片像素，粗细按屏幕上看到的算即 `尺寸 / 缩放`，马赛克用当前图缩小再放大；颜色和粗细跟截图共用 localStorage `shot-mark`，另可自定义颜色）、边框（背景纯色/渐变、边距和圆角按短边百分比、阴影；`isNoFrame` 只看边距和圆角）、尺寸（锁定比例、百分比、长边预设；缩小时先逐级减半再画）、取色（点击复制色值，最近 12 个记在 `image-picks`）、去背景（2026-11-18 加，在裁剪旋转后面；没有模型——Windows 自带的抠图接口要 Copilot+ 电脑和 MSIX 打包，用不了；人像模型 MODNet 加运行库要 +17MB 且不认卡通，用户不要）：`src/cutout.ts` 从四周往里按颜色去掉背景（`fill` 4 连通，背景色取往里 `frameInset`（1%、至少 3 像素）那一圈最多的颜色，四周另有一圈细边框——用户的 AI 图就有——时边框带着一起去），被轮廓围住的同色部分（白裙子）保留；「点选去除」按点到的颜色再去一片；边缘按离背景色的距离给半透明并减掉背景色（`soft`，不留白边）；滑块 1–100 经 `tolOf` 换成颜色距离。手动「擦除 / 恢复」画笔画在两张图片大小的画布上（画一张时从另一张擦掉，先后不乱），`compose` = 按颜色去掉后的图 + 恢复笔画处的原图 − 擦除笔画。应用后是 `{ kind: "cutout", out }` 操作（存结果画布，重放时照抄）。只有点进这个面板时自动去一次背景；打开图片、撤销、应用之后都是原样，要勾「从四周去掉背景色」。「设为桌宠形象」（`asPet`）：裁掉四周透明、最大 512、PNG 经 `Settings.AddPetImage` 存进 appearance 文件夹并设为当前形象。单测在 `image.test.ts`，CDP `.dev/js/cutout-ui.js`（sed 把 FILE 换成图片路径，Windows 路径的反斜杠要写成 \\\\）。去水印（`src/inpaint.ts`，PatchMatch 补图：只在水印外扩一圈的框里做；金字塔从粗到细，最粗一层至少 40 像素、可取样的块至少是要补的 2 倍（太粗结构就定歪，太少层大洞会出竖条纹）；每层若干轮「PatchMatch 找最像的块 + 按相似度加权平均」，最后一轮权重更偏向最像的块；RGBA 一起算，透明背景补出来还是透明）：涂抹/框选/擦掉选区（红色），「去除」前把选区外扩 2 像素，结果存成 `{ kind: "inpaint", out }`。2026-11-18 在用户的 AI 图上调参（`.dev/js/wm-tune.ts` + `wm-{tight,box}.bin`，测完删了原图裁片）：只涂文字笔画时平均色差 18.7，整块框选 21.7，后者会留一块柔和的糊痕；补丁 9×9 不比 7×7 好、慢三倍。打码（`censor` 操作，数据是框或笔画、样式、强度，可重放）：马赛克/模糊、框选/涂抹、强度按短边比例，设置记在 localStorage `image-censor`。CDP `.dev/js/watermark-ui.js`（同样 sed FILE；在图上画假水印后框选去除，再打码，返回前后的裁图）。调色/边框/裁剪框没点「应用」时，换面板、保存、复制都会自动应用（`commitPending`）。滚轮缩放（以指针为中心）、空格或中键拖动平移，调色/边框/尺寸面板左键也是平移；适应窗口时跟着窗口大小变（`fitted`）。保存对话框：PNG/JPG/WebP、质量（记在 `image-export`）、按当前设置实算的文件大小；「另存为」（`ImageEdit.Save`，默认在原图旁边叫「… 编辑.xxx」，重名加 (2)，非文件来源默认截图的保存文件夹）、「覆盖原图」（`ImageEdit.Overwrite`：只认在这里打开过的文件、格式要和扩展名一样，先写 `.tmp` 再改名）；JPG 先铺白底。复制走 `ImageEdit.Copy` → `copyPNG`（PNG；开了截图的「复制时附带图片文件」时也带文件）。最多 1.2 亿像素。CDP 测试 `.dev/js/image-ui.js`（粘贴一张合成图后走一遍各面板、导出、复制、撤销重做、imgedit scheme 和覆盖的限制）、`image-handoff.js`（剪贴板历史的「编辑」）、`image-big.js`（6000×4000 的耗时）、`image-overwrite.js`（在 TEMP 的副本上覆盖，sed 把 FILE 换成副本路径）、`image-reopen.js` + `image-modes.js`（截图用：sed 把 MODE 换成 mark/frame）
- 图片编辑的另外两个视图（2026-11-18 加，工具页顶上的标签「编辑图片 / 创造拼图 / 合并文档」，记在 localStorage `image-view`；`imageedit.ts` 的 `switchView` 切换时先 `leave()` 清掉上一个视图的监听，各视图的数据都是模块变量，切回来还在；别的工具送来的图片总是切到「编辑图片」）。三个视图共用的画布、读图、背景、保存对话框（`exportDialog`）、标注的粗细/颜色面板（`penHTML`/`showPen`/`penEvent`）在 `src/imgutil.ts`；截图、编辑图片、拼图三处共用 `marks.ts` 的 `pen`/`setPen`（粗细和颜色，记在 `shot-mark`）、`newMark`/`dragMark`/`slip`（开始、跟随指针含 Shift、太小算手滑）和 `textBox`/`styleTextBox`（输文字的框，`field-sizing: content` 自己长，Esc/Ctrl+Enter 结束）。
  - `src/collage.ts`「创造拼图」：布局是一棵树（格子 `Leaf`，或沿 x/y 一分为二的 `Split`，`ratio` 是前一半的比例），15 个模板；选中格子可左右分/上下分/删格子（兄弟占过来，图片挪到空格子或变浮动图片）/换图，拖格子间的线改比例（`lineAt` 取离指针最近的那条，T 字路口不会抓错），拖格子里的图片平移、拖到别的格子交换、滚轮放大（`fx/fy/zoom`）；画布比例和宽高、间距/边距/圆角（按短边千分比）、背景。标注（共用 `marks.ts`）和浮动图片都是图层（`layers`，下面的在前），选择工具下点中可拖动、浮动图片拖右下角缩放、双击文字重新编辑；「图层」页列表可拖动排序、置顶/上移/下移/置底（Ctrl+] / Ctrl+[，加 Shift 到顶/底）、隐藏、删除，拼图格子总在最底。撤销是整个模型的 JSON 快照（`past`/`future`，图片在 `pics` 里不进快照），拖动一次算一步。添加的图片按顺序放进空格子，放不下的变浮动图片；图片读进来最长边缩到 4096。保存/复制/「送去编辑」（`openCanvas`）都先 `paint(c, true)` 画一张不带空格子占位的图，保存走 `ImageEdit.SaveFile`。CDP `.dev/js/collage-ui.js`；布局树的纯函数在 `src/layouttree.ts`（分割、删格子、换模板、cover），单测 `bun test ./.dev/test/image.test.ts`（同一文件也测 `src/geom.ts` 的裁剪框/长图计算和 `marks.ts` 的 `dragMark`/`slip`；`bun test` 要写 `./` 开头的路径，否则当成名字过滤）
  - `src/merge.ts` + `imagedoc.go`「合并文档」：拖进/添加/粘贴的图片成卡片，HTML5 拖放排序、按名称排序、倒序、每张可右转、移除可撤销；页面只留 320px 的缩略图，导出时一张张重新读（文件按路径 `ImageEdit.OpenPath`，粘贴的留着 Blob）。导出为 PDF / PPT：先 `ImageEdit.DocBegin`（保存对话框）拿到任务，每页按设置（最长边、JPG 质量或 PNG）编码后 `DocAdd`，最后 `DocFinish` 由 Go 写文件（先写 `.tmp`）；页面大小 跟图片一样/A4 纵/A4 横/16:9、边距 无/小/大，`docLayout` 算版面（PDF「跟图片一样」每页是图片按 96 dpi 的大小加边距；PPT 只有一个幻灯片尺寸，按第一张的比例、长边 13.33 英寸）。PDF 是手写的（JPG 直接 DCTDecode，PNG 解码后 Flate 压 RGB，有透明时加 SMask）；PPTX 也是手写的最小包（一个母版、一个空白版式、一个主题，每页一张图），python-pptx 能读、WPS 能打开并导出（`.dev/pptx-wps.ps1` 用 WPS 的 COM `KWPP.Application`）。PDF/PPT 里的图片只能 JPG/PNG，WebP 只给「长图」：从上到下按最宽的那张（最多 8000）拼成一张，超过 32000 高就整体缩窄，保存走 `SaveFile`。单测 `imagedoc_test.go`（版面、写出 PDF/PPTX、`TOOLBOX_DOC_OUT` 设了就把文件留下来看）；整条导出的实测 `.dev/merge-run.sh <pdf|pptx|image> <扩展名>`：CDP 跑 `merge-ui.js` 开始导出，再用桌面会话的 `TestDeskSaveDialog`（`imagedoc_desk_test.go`，`-save <路径>`，按窗口句柄往「导出文档/保存图片」对话框里填路径点保存，不往前台发按键）存到 `.dev/doc-out`。测完 `.dev/js/image-clean.js` 清空三个视图
