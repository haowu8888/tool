# 断开物理屏

从 CLAUDE.md 拆出来的细节：改这部分代码前先读。

## 实现

- `virtualscreen.go` + `vdisplay_windows.go`：工具「断开物理屏」，类似 RustDesk 隐私模式 2。用 RustDesk 自带的 usbmmidd 驱动插入虚拟显示器（`DeviceIoControl` 0x10 插、0x00 拔），`ChangeDisplaySettingsEx` 把它设为主屏，物理屏改成 0×0 放到 (10000,10000) 断开（Win11 24H2 要先设新主屏）。切换前把原布局写进 `%APPDATA%\Toolbox\virtual-display.json`，`Stop`、`OnQuit` 和下次启动（`restoreDisplaysLeftOver`）都靠它恢复。Windows 按「接着哪些显示器」记布局，断开时用 `CDS_UPDATEREGISTRY` 写下的「物理屏 + usbmmidd 屏：物理屏断开」这条，恢复后不一定被改掉，之后 RustDesk 隐私模式 2 一插虚拟屏物理屏就被断开，报 "This only virtual display cannot be plugged out" 并黑屏（2026-11-12 用户遇到）。所以 `restore` 在拔虚拟屏之前先确认物理屏亮了（不亮就 `SetDisplayConfig(EXTEND)`），再用 `saveDisplayConfig`（`QueryDisplayConfig` + `SetDisplayConfig(SDC_SAVE_TO_DATABASE)`）把这个组合的布局存成两屏都亮；拔掉后仍没有物理屏再 EXTEND。`Toggle`（快捷键、托盘、悬浮球）在没开启但一块物理屏都没亮时改为 `rescueDisplays`：EXTEND，不行再 INTERNAL，点亮后保存布局并拔掉所有 usbmmidd 屏，用来救 RustDesk 残留的虚拟屏；开启失败时：页面按钮弹对话框（`showStartFailed`，没有物理屏时说明屏幕已经是暗的、多半是 RustDesk 隐私模式，并给「强制找回物理屏」）；页面下方「显示器」列表每 2 秒调 `VirtualScreen.Displays`（`listDisplays`：枚举所有输出及其显示器，按显示器 ID 去重，笔记本屏会挂在好几个 Intel 输出下；0×0 算断开），顶部写本机屏幕亮/暗及原因，虚拟屏标出是工具箱插的还是其他程序（多半是 RustDesk）。快捷键/托盘/悬浮球触发的失败广播 `virtualScreenFailed` 让页面弹同一个对话框，并弹系统通知（窗口可能藏着）；强制找回成功或失败也弹通知。断开后一直保持到用户恢复（2026-11-16 改，以前是显示器被别人改了就自动结束）：`watch` 每秒、以及 Windows 报显示器变化时（`displaysChanged`）检查，虚拟屏没了或物理屏回来、600ms 后还是这样就 `hold`——没有虚拟屏就重新插一块（分辨率用 `Size`，平时跟着远程那边改的分辨率记），再把物理屏断开；一分钟内超过 5 次就放弃并恢复（`gaveUp`）。RustDesk 1.5.0 最后一个会话结束时 `reset_all` 会按它自己记的插入次数拔 usbmmidd 屏（这个计数被工具箱拔过它的屏之后就不准了），所以工具箱插的那块也可能被拔掉，Windows 随即点亮物理屏，`hold` 一两秒内再断开。工具箱和 RustDesk 断开物理屏后，物理屏在 `EnumDisplayDevices` 里连 ACTIVE 都没有，所以工具箱开着时 RustDesk 隐私模式 2 会报「没有物理显示器」开不了，反过来工具箱也报错。`Toggle` 在没开启、物理屏全暗时：RustDesk 正连着（`rustdeskConnected`：有当前用户能读到命令行的 `rustdesk.exe --cm`，用 `NtQueryInformationProcess` 60 读；服务和 `--server` 是 SYSTEM 的读不到）且有虚拟屏就不动显示器，`failed` 把窗口调出来弹对话框（系统通知被关了），由用户点「强制找回物理屏」；否则 `rescueDisplays`，一块显示器都没有（没有虚拟屏）时也救。恢复和找回都用 `lightPhysical` 确认物理屏亮了：等不到就 EXTEND、INTERNAL，最后 `attachPhysical` 给每个接着显示器的输出直接设最大分辨率。虚拟屏分辨率：主物理屏的分辨率它没有（2520×1680 就没有）时用 1920×1080，以前会停在 1024×768。Windows 记着「物理屏 + usbmmidd 屏：物理屏断开」时，虚拟屏一插上物理屏就被断开，所以 `switchToVirtual` 用插之前读到的物理屏模式；`restore` 时虚拟屏已经不在（被 RustDesk 拔了、放弃保持、上次异常结束）就先插一块再点亮物理屏、保存布局，否则这条布局留着，下次 RustDesk 开隐私模式 2 还是黑屏。锁屏（`mygo.Power.OnLockScreen` → `setLocked`，回调在主线程，里面不能拿 `v.mu`）：用户的 RustDesk 开了「会话结束后锁定」，安全日志 4800 和会话结束同一秒，锁屏界面收不到全局快捷键，物理屏又断着，本机就既看不见也按不回来（2026-11-16 用户说的「退出 RustDesk 后 Ctrl+Alt+B 解除不了」就是这个）；所以锁屏期间 `watch` 用 `someoneHere` 看本机键鼠：锁屏 3 秒后有过输入（`mygo.Power.IdleTime` = `GetLastInputInfo`）且没有 RustDesk 连着就恢复物理屏、结束断开（单测 `virtualscreen_test.go`；锁屏事件和「没人动就不亮」实测过，锁屏界面上按键这一步要人在场，没测到）。快捷键 `Ctrl+Alt+B`、托盘「断开/恢复物理屏」

## 调试

- `displays.ps1`（任务 `ToolboxDisplays`）：列出显示设备、状态和当前模式到 `.dev/displays.txt`，看物理屏是否断开
- 显示器相关的实测写成 Go 测试 `vdisplay_desk_test.go`，经 `desktest.ps1` 在桌面上跑：`-test.run TestDeskDisplays -test.v -test.count=1 -desk <步骤>`，步骤有 `res`（主屏改成 1920×1080 几秒再改回）、`rd-on` / `rd-off`（照 RustDesk 1.5.0 源码做隐私模式 2 开/关时的那几步，不含键鼠钩子）、`unplug` / `plug`（拔/插一块虚拟屏，模拟 RustDesk 会话结束时的 `reset_all`）、`lock`（`LockWorkStation`，之后要用户自己解锁）、`attach`（`attachPhysical`）、`fake-cm`（把 cmd.exe 拷成 `.dev\rd-fake\rustdesk.exe` 后用它装一分钟 `--cm`；从 SSH 会话启动的进程是高完整性的，应用读不到它的命令行，所以要由这个步骤在桌面上启动）、`probe`（悬浮球窗口的大小和 min/max）、`shot`，每步在 `.dev\desk-<步骤>.png` 留一张全屏截图。配合 `.dev/js/vs-start.js`、`vs-state.js`（开启、看状态和显示器列表）、`vs-dialog.js`、`vs-rescue-click.js` 和 `hotmsg.ps1` 发 1。会让用户的屏幕黑几秒到几十秒。悬浮球窗口实际是 103×78 像素（Windows 给带标题栏样式的窗口留的最小宽度，`MinWidth` 压不下去），不是黑框的原因
